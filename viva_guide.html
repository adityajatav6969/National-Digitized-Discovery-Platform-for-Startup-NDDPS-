1. Executive Summary & Problem-Solution Overview

Problem Statement: India is home to 100,000+ startups, and the Government of India (DPIIT, MeitY, DST, SIDBI) offers 50+ funding grants, subsidies, and incubation schemes. However, founders struggle with fragmented information, unvetted registries, and lack of awareness of which schemes their startup is actually eligible for.

Solution (NDDPS): A centralized, digitized national discovery platform where startups undergo DPIIT-aligned administrative moderation, are discoverable via multi-faceted real-time search, and are automatically matched with government grants using an intelligent domain-, stage-, and state-based recommendation engine.

4. Top Viva Cross-Questions for Aditya

Q1: Why did you choose JWT over traditional Server-Side Sessions?
Ans: Server-side sessions require state storage (in memory or Redis), creating memory bottlenecks as users scale. JWT is completely stateless; the signed token carries the user ID and role, allowing instant horizontal scaling and eliminating database lookups on every request.
Q2: How does your password hashing with bcryptjs protect against rainbow tables?
Ans: We use 10 salt rounds. Salt is random cryptographic data added to the password before hashing, meaning two identical passwords will result in completely different hashes, making precomputed rainbow tables useless.
Q3: Why did you use PATCH instead of PUT for admin verification?
Ans: REST conventions dictate that PUT replaces the entire resource, whereas PATCH is designed for partial updates. In admin verification, we only modify verificationStatus and adminRemarks without mutating the rest of the startup profile.
Q4: How does your system prevent crashing if the local MongoDB database is down?
Ans: I implemented a dual-mode controller pattern. On startup, Mongoose attempts connection with a 2.5s timeout. If it fails, the server toggles global.useInMemory = true and seamlessly routes controller operations to inMemoryStore.js with identical signatures.

4. Top Viva Cross-Questions for Arjun

Q1: What is debouncing in your SearchBar, and why is it essential?
Ans: Debouncing delays the API call until the user stops typing for 300ms. Without debouncing, typing a 10-letter word would trigger 10 separate API requests to the backend, causing unnecessary network traffic and server lag.
Q2: How do your filters synchronize with the backend query parameters?
Ans: When filter checkboxes change, DiscoverPage.jsx aggregates them into arrays, joins them into comma-separated strings (e.g. ?domain=FinTech,AgriTech&stage=Seed), resets the page to 1, and calls getStartups(params) via Axios.
Q3: How did you implement responsive design for the sidebar on mobile devices?
Ans: Using Tailwind CSS grid utilities: grid-cols-1 lg:grid-cols-4. On desktops, filters take 1 column and cards take 3 columns. On mobile screens, filters collapse behind a toggle button to preserve screen real estate.

4. Top Viva Cross-Questions for Anushri

Q1: How does your scheme mapping algorithm calculate match scores?
Ans: The algorithm queries schemes where eligibleDomains includes the startup's domain and eligibleStages includes the startup's stage. Domain match awards +40 points, stage match awards +35 points, and state match awards +25 points (maximum 100 points). Schemes are sorted in descending order of match percentage.
Q2: How does the analytics aggregation pipeline work in MongoDB?
Ans: We use MongoDB aggregation pipelines with $group: { _id: "$domain", count: { $sum: 1 } } to compute distributions on the database server directly, minimizing network payload compared to fetching all documents to the application layer.

3. Key HTTP Status Codes Used in Project

  • 200 OK: Successful query retrieval, profile update, or admin approval.
  • 201 Created: User account successfully registered or startup profile created.
  • 400 Bad Request: Missing required fields or duplicate email on registration.
  • 401 Unauthorized: Missing, invalid, or expired JWT Bearer token.
  • 403 Forbidden: Non-admin user attempting to access administrative verification endpoints.
  • 404 Not Found: Requested startup or scheme ID does not exist in database.
  • 500 Internal Server Error: Unhandled server-side exception.
